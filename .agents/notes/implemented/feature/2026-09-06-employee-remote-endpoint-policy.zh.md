# Agent Note: 部署端持有的 Remote 端点权限

Status: implemented

[English](2026-09-06-employee-remote-endpoint-policy.md) | 中文

## 问题

员工对话运行时即使只向模型提供业务读取工具，也可能暴露 Host 设置、预设选择或工作区操作。隐藏浏览器控件不会移除 HTTP 调用，而仅限制 HTTP 路径也无法限制同一条 WebSocket 承载的逻辑流。

## 决策

[Gateway](../../../../packages/api/gateway/README.zh.md) 接受部署端持有的 `allowedEndpoints` 名单。默认值 `all` 保持 Host 分派不受限制；显式空名单拒绝全部端点。名称精确匹配并经过 schema 校验。Gateway 在构造时复制名单，不从请求参数或调用方可变数组中读取权限。

分派器在一元调用和流式调用中，都先检查权限，再解析描述符、Context 和查找参数。保留的事件传输端点分别执行检查。拒绝的调用返回 `gateway/forbidden`，不会执行业务方法。严格生成的描述符与 SRC 标记使用同一套强制检查。

## 考虑过的替代方案

**隐藏控件或移除模型 schema。** 调用方可以直接发送底层 RPC；展示方式不构成执行权限。

**仅过滤反向代理路径。** 多条逻辑流共享同一个 WebSocket 路径，本地传输也可以不经过 HTTP 而调用同一个分派器。

**将其做成多用户授权服务。** 端点权限没有员工身份或文档所有权上下文。这些职责应由隔离部署和业务所有者承担，而不是由端点名称检查承担。

## 后果

该策略为专用员工 Host 提供默认拒绝的 RPC 名单，同时保持普通配置不变。它不会对进程实施沙箱限制、保护无关路由，或把共享 Host 变成多租户系统。允许的方法仍可能通过自身参数分派任意操作，因此员工组合必须审查命令、预设、工作区、文件和插件 API，而不能放行整个命名空间。

允许 `$events` 会暴露完整的已配置事件名单，不代表按员工过滤。活动流保留打开时的权限，直至取消或 Gateway dispose（资源释放）。替换或撤销员工访问需要这份不可变名单之外的生命周期控制。

## 验证

包内的 Loader fixture（测试前置数据）覆盖真实 Connection HTTP 与 Gateway WebSocket 分派、直接调用、严格定义和 SRC 定义、保留端点、浏览器认证以及 Gateway dispose。通过分派器之外的文件验证拒绝写入没有产生影响。两个并发加载的 Host 持有不同的凭据所有者和测试文件；这不是生产员工会话或操作系统隔离测试。

拒绝回归用例在未修改的分派器上失败，因为被禁止的方法实际执行。恢复策略后，专项测试通过。没有修改模型提示词、工具 schema 或会话事件；传输预期输出归属于包内测试，而不是模型文本记录。
