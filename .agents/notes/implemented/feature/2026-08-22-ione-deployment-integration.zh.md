# Agent Note: IONE 部署集成

Status: implemented

[English](2026-08-22-ione-deployment-integration.md) | 中文

## 问题

IONE Harness 运行在经过 Frappe 认证的反向代理之后，使用本地 SearXNG 服务而非商业搜索 API，并向远程浏览器提供设置界面。默认浏览器信任规则会让这些设置只在进程内生效，默认搜索卡片面向需要凭据的提供方，而内测声明不属于 IONE 产品体验。

## 决策

`@deepseek-ai/dsh-web-search-searxng` 向 `ctx.web` 注册 `searxng` 提供方，通过设置领域发布其 `baseURL`，每次操作读取当前接口地址，拒绝重定向，并且只把 HTTP(S) 引用映射到可移植网页结果。“插件”设置页在 `web-search-searxng` 下提供只包含接口地址的 SearXNG 卡片，不提供 API 密钥或单次请求次数控件。

浏览器设置底座为 loopback 连接以及携带公开构建标志 `DSH_CLIENT_IONE_TRUSTED_SETTINGS=1` 的构建选择 Host 持久化。该标志只适用于由 Frappe 认证和反向代理建立信任边界的 IONE 部署；其他远程浏览器仍使用内存模式。

模型设置插件不注册版本化内测声明。模型页面和按条件出现的提供方引导保持独立可用。

## 安全边界

SearXNG 请求使用 `redirect: error`，因此配置的源站不能把搜索词或请求头转发到其他目标。提供方只接受绝对 HTTP(S) 源站，并丢弃非 HTTP(S) 结果网址。受信任设置构建标志不包含凭据，也不会自行授予认证；它只会在部署已经提供认证代理边界之后改变客户端持久化方式。

## 验证

提供方测试覆盖请求构造、响应规范化、动态设置、故障、卸载，以及使用真实 HTTP 服务验证拒绝重定向且目标端未被访问。客户端测试固定受信任代理的持久化选择、设置 scope 传递、内测 slot 缺失，以及只包含接口地址的 SearXNG 卡片。

## 考虑过的替代方案

**保留商业搜索提供方并存储其密钥。** 这会继续保留外部凭据，也没有使用部署中已运行的 SearXNG 服务。

**把所有远程浏览器都视为可信。** 这会削弱未通过 Frappe 认证路由部署时原有的 loopback 安全边界。

**通过持久化确认来关闭内测声明。** 声明仍然可达，并会在版本变化后再次出现；取消注册该 slot 才能直接匹配 IONE 产品契约。

## 结果

IONE 可以通过经过认证的公开入口配置本地搜索和其他 Host 设置，不会退回浏览器本地状态，也不需要商业搜索凭据。运维人员只能在匹配的代理拓扑中设置受信任设置标志，并需要确保 Harness 进程能够访问 SearXNG JSON 接口。
