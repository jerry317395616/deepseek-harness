# Agent Note：Frappe 官方文档知识库

Status: implemented

[English](2026-09-02-frappe-docs-knowledge-base.md) | 中文

## Problem

Harness 已经可以检查当前 Native Bench 源码和获准的 Frappe 数据，但框架与产品的官方指导仍依赖实时网页搜索。该方式不确定，无法保留同步后的版本清单，还可能把当前公开文档与已部署应用的运行行为混在一起。把整站文档复制进系统提示则会产生无界且不稳定的模型前缀。

## Decision

`@deepseek-ai/dsh-tool-frappe-docs` 读取由部署管理的本地知识库。独立运维命令会同步官方 `docs.frappe.io` 站点地图和每个文本页面的 Markdown 版本，并写入 SQLite。索引保存标题、产品路径、版本路径、语言、更新时间、官方来源链接、页面内容以及按标题划分的有界章节。FTS5 BM25 搜索支持按产品、版本和语言筛选。刷新失败时会保留旧的可用页面；增量同步会按站点地图日期跳过未变化页面。

模型获得三个只读操作：有界搜索、有界页面或章节读取、索引状态。任何工具都不能触发同步、选择知识库路径、抓取其他来源或写入索引。搜索和页面结果会保留官方来源链接与版本元数据。通用工具卡片直接渲染结构化结果，不需要本包增加 Client 组件。

提示区段规定证据顺序。已部署行为和业务计算首先使用 `/home/zyd/frappe/native-bench/apps`，然后使用当前 Frappe 元数据和获准业务记录。官方文档在这些来源之后解释框架与产品规则；回答必须说明版本差异，不能把当前公开文档当作运行事实。

`@deepseek-ai/dsh-ione-frappe-docs` Bundle 提供一个默认停用的补丁行。部署只有在完成索引同步后才启用该行，并提供知识库绝对路径。该索引不是 Frappe 数据库，不会新增或修改 DocType。

## Consequences

- Frappe、ERPNext、Education、HR、CRM、Desk、Bench、API 及其他官方产品问题可以使用一个保留原始链接和更新时间的本地检索语料库。
- 页面只有经过明确搜索和读取工具才进入请求，因此模型上下文保持有界。
- 首个版本使用词法检索，中文问题应包含或推导相应英文 Frappe 技术词。以后可以增加多语言向量提供方，而无需修改工具结构。
- 定时运维进程可以在不重启 Harness 的情况下刷新语料库；后续工具调用会读取更新后的 SQLite 索引。
- 当前部署仍以运行源码和站点证据为准，因此文档知识库不能作为修改数据或结构的依据。

## Alternatives considered

- **把整站复制进系统提示**——否决，因为语料库过大，而且每次更新都会破坏稳定的提示前缀。
- **每次文档问题都使用实时网页搜索**——否决，因为可用性、排序、版本清单和引用会随请求变化。
- **允许模型同步索引**——否决，因为抓取属于带有网络负载和持久写入的运维生命周期，而不是面向模型的只读能力。
- **把语料库存进 Frappe DocType**——否决，因为文档检索不需要修改应用结构，而且 Native Bench 规则禁止新增或修改 DocType。
