# Agent Note: 请求所属的员工 Agent 轮次

Status: implemented

[English](2026-09-07-employee-authenticated-turns.md) | 中文

## 问题

账号所属的会话历史不等于执行身份绑定。Host 提示回执只确认进入队列；固定账号的 Frappe 客户端不能区分共享同一运行时 UID 的员工。

## 决策

[员工 API](../../../../packages/api/session-controller/src/employee-access.ts)可选择在部署拥有的只读预设下接受文本提示。[轮次执行器](../../../../packages/api/session-controller/src/employee-turns.ts)为每个会话预留一个请求，分配服务端生成的消息关联编号，并在转录之外保留已验证主体和不透明登录。首条准入消息绑定一个编号轮次和 Agent；无关的排队或插入消息不能继承其授权。请求等待整个 Agent 空闲，清理后不保留凭据。重启不能恢复授权。

每次模型请求和读取都复查同一账号。限定作用域的读取工具在执行体中检查绑定的 Agent，并调用共享身份服务，而不是按 UID 绑定的客户端。不可被允许规则覆盖的检查拒绝其他工具及无 Agent 身份的调用。工具调用和结果使用已有会话事件，不需要修改事件格式或 Frappe 结构。退出会取消对应活动。断开、期限和销毁会取消并等待本地任务；已接受的远程读取仍受身份服务独立期限约束。

## 考虑过的替代方案

图片提示需要部署显式开启，并使用同一个请求所属轮次。原生图片准入校验并持久化图片内容；员工执行器在这些内容之外保留身份与工具限制。HTTP 提示大小上限独立于其他操作配置，传输输入最多接受四张图片。图片是输入数据，不是授权来源。

**使用部署全局的 Frappe 用户。** 两个登录同时执行时会返回另一名员工的记录。身份服务独立解析每个不透明登录，Frappe 仍负责文档权限。

**保留授权直到会话结束。** 会话会跨越退出登录和进程重启。请求所属凭据随活动 HTTP 操作结束而失效，不能授权回放的队列消息。

**开放普通 Host 提示 API。** 其队列回执不能证明员工身份或逐消息完成状态。独立接口从准入管理到完全静止，拒绝重叠请求，不把共享运行区间归属于多个用户。

## 影响

[进程测试](../../../../apps/cli/tests/profiles/employee-readonly/employee-turns.expected.e2e.ts)验证两个限定身份、并发活动账号、重叠拒绝、取消、退出及结束后的复用。[单元测试](../../../../packages/api/session-controller/tests/employee-turns.host.spec.ts)覆盖无关轮次拒绝、模型请求前停用、直接工具执行体拒绝及读取后撤销。[记录会话](../../../../snapshots/web/employee-shared-readonly/session.jsonl)固定经过认证的查询和权限范围内的结果。进程场景中的测试替换模型输出和业务数据，不替换 Agent 或工具运行时。

这扩展[归属预览](2026-09-07-shared-session-ownership.zh.md)，不是其正式部署。响应报告活动结束及历史游标，不表示业务成功。任意代码、结构变更、非图片文件及全局员工事件流仍未开放。单 UID 部署保持应用层区分，不提供对同 UID 下任意代码的隔离。
