# Agent Note: Native Bench 员工身份断言续期

Status: implemented

[English](2026-09-06-native-employee-assertion-renewal.md) | 中文

## 问题

员工业务读取需要短期有效、固定绑定的身份。依赖 Docker 且改写同一份共享模型凭据的续期脚本，无法为 Native Bench 员工运行时提供独立断言。只修复其目录仍会保留共享集成身份。

## 决策

[部署续期程序](../../../../packages/extensions/tool-native-bench-frappe/python/native_actor_refresh.py)加载一份私有配置，通过 Frappe ORM 读取精确指定的已启用系统用户，并签发与已安装 I-ONE 校验器兼容的断言。程序在发布到一个私有目标前验证结果。签名材料和断言只存在于部署进程内部及仅所有者可访问的文件中，不进入模型参数、标准输出或标准错误。

原子发布使已经打开文件的读取者能够读完完整旧文件，后续读取者则获得完整新文件。安全打开目标后，续期失败会删除旧断言。配置或打开失败、强制终止的影响仍由旧有效期限制。调度器负责串行执行和生命周期；删除绑定时需要停止对应续期，并处理剩余文件。

这是特权部署操作，不是 Cordis 工具、远程接口或员工登录。它不创建账号，不修改角色，不保存业务记录，也不改变 DocType。[登录分流决策](2026-09-06-employee-login-routing.zh.md)仍要求独立主机和经过验证的代理授权。

## 考虑过的替代方案

**修复旧 Docker 命令。** Native Bench 是当前运行环境，而旧命令续期的是共享集成身份，不是单个员工身份。

**将签名材料放入每个员工主机。** 被入侵的员工进程可能签发其他身份。签发程序必须位于员工可控制的进程和配置之外。

**在已知续期失败后保留有效断言。** 签发程序已发现账号不可用或校验失败后，这会继续保留访问权限。删除已验证的旧文件可消除该时间窗口；签发进程不可用时，仍由有效期和读取端的实时账号检查限制访问。

## 影响

辅助程序无需新数据模型即可支持源码管理的续期。它增加了一个需要部署方隔离、调度和监控的特权进程。仅靠 POSIX 私有文件无法隔离共享同一操作系统身份的进程，辅助程序也不会授权 Web 会话或撤销已建立的流。

无真实凭据的测试覆盖身份绑定、有效期内容、校验拒绝、私有文件原子发布、撤销、脱敏的 CLI（命令行界面）失败和 Native 上下文清理。还需要真实站点检查来确认与已安装 I-ONE 校验器的兼容性；这些单元测试不能替代员工登录或主机隔离测试。辅助程序不改变模型 schema 或会话事件，因此其 CLI 预期输出保留在所属包内；现有业务拒绝会话记录提供读取端回归验证。
