# Agent Note: 员工只读 Web 组合

Status: implemented

[English](2026-09-07-employee-readonly-composition.md) | 中文

## 问题

仅限业务的模型适配器不能约束标准 Web profile 的编程预设、Host RPC 或共享持久化。部署需要明确的组合，以便同时检查模型能力和 Remote 接口范围。

## 决策

提供可选的[员工覆盖配置](../../../../apps/cli/config/examples/employee-readonly/cordis.yml)及运维管理的相邻预设。覆盖配置排除内置和用户预设根目录，禁用编程与编辑能力提供方，并使用精确的 Gateway 接口列表。预设提供完整的只读业务角色提示，且仅挂载 Native Bench Frappe 业务读取器。普通 Web 默认行为不变。

每个员工部署拥有独立进程、工作目录、状态根目录、浏览器凭据和签名 Frappe 身份。文档访问仍受适配器现有的签名身份及 Frappe 权限检查约束。覆盖配置是受信任代码，不得与未经审查的维护补丁混用。

可选的 [Linux 只读代理](../../../../packages/extensions/tool-native-bench-frappe/python/employee_read_broker.py)为 UID 绑定读取提供可信后端。员工配置方案通过 `DSH_EMPLOYEE_BROKER_SOCKET` 选择其[套接字客户端](../../../../packages/extensions/tool-native-bench-frappe/src/broker.ts)，此时禁止直接配置调用者身份或身份断言文件。代理拒绝调用者自选身份及写操作，将记录权限交给既有读取程序，并在返回数据前检查账号状态。连接失败不会回退到直连 Bench。系统账号配置和凭据隔离仍是独立要求。

## 考虑过的替代方案

**保留标准预设，只减少按钮。** 模型工具和直接 Remote 调用拥有的权限独立于浏览器展示。

**禁用所有预设。** Agent 组合可能继承全局层；固定且封闭的预设根目录让预期工具归属明确。

**宣称实现完整多用户隔离。** 私有进程状态不会隔离同一 UID 的文件系统访问，也不会实现员工 SSO 或撤销活动连接。

## 影响

交付产物是经过 API 测试的预览。它不启用生产服务，不创建 DocType，不修改业务记录，也不授予员工角色。标准 UI 控件可能仍然可见，但对应操作会被拒绝。真实浏览器、代理、模型数据及真实账号授权验收仍由部署负责。

标准组合变化时，必须复审接口列表及显式禁用项。录制会话夹具固定完整模型提示和工具清单，以发现意外的能力或角色范围扩张。

## 验证

真实构建后的 CLI 测试启动两个私有 Web 进程，仅模拟模型提供方。测试拒绝 HTTP 和 WebSocket 修改接口、其他预设、模型发出的 Shell 调用、外部凭据及其他实例会话读取。测试检查文件系统中没有调用效果，并在新进程中重载持久化会话；允许既有的恢复种子标记，而先前记录保持逐字节一致。

无密钥 Web 录制会话测试通过同一 CLI 覆盖配置回放自己的会话记录，并比较持久化会话、完整提示及工具模式。测试使用模拟身份，不使用生产数据。它们证明的是应用组合，而非真实员工登录或操作系统沙箱。

经 root 授权的 Native Bench 手工验收，在两个临时无登录 UID 下运行已构建套接字客户端，并由 Bench 所有者运行真实代理。验收核对教师的 92 人班级名单、班外及跨角色访问拒绝、身份注入与未绑定 UID 拒绝、账号停用，以及无法访问 Bench 凭据和其他员工状态。两个 Frappe 测试账号最终均停用且无会话；业务和权限指纹保持一致，临时系统账号及目录均已删除。这不代表完整 Web 进程沙箱或登录后浏览器验收通过；正式入口未改变。
