# Agent Note: 显式单账号身份策略

Status: implemented

[English](2026-09-07-single-user-identity.md) | 中文

## 问题

部署负责人要求 Bench 和一个共享 Harness 使用同一个非 root Linux 账号。独立运行时所有权无法描述这种部署，但静默删除 UID 检查会掩盖安全边界。

## 决策

共享身份服务接受可选 `uid_policy`，默认值为 `separate`。显式 `single-user` 要求运行时 UID、身份服务有效 UID 及每个已配置 Bench 的所有者都对应同一个非 root 账号。内核对端检查、签名登录校验、固定的逐账号读取及只读范围仍为必需。[指南](../../../../docs/user/guide/employee-shared.zh.md)定义配置契约。

此部署选项补充[账号所属预览](2026-09-07-shared-session-ownership.zh.md)，不开放员工提示执行。协议不在响应中提供密钥，但共享 UID 无法阻止不受限的本地代码读取相同私有文件。

## 考虑过的替代方案

**删除所有权校验。** 这会静默削弱现有部署，并在操作者没有明确选择时接受混合所有权。

**要求另一个 Linux 账号。** 这提供更强的操作系统边界，但不符合部署要求。需要该边界的操作者仍可使用默认独立模式。

## 影响

配置测试覆盖显式准入、默认隔离、身份服务与 Bench 所有权不匹配、root 拒绝及无效策略值。已有账号、撤销、身份伪造和禁止写入测试继续验证未改变的请求路径。此选项不能使面向员工的任意 shell 或文件系统工具变得安全；正式路由及逐轮 Agent 身份绑定不属于本次变更。不包含正式配置或 Frappe DocType 变更。
