# Agent Note: 应用负责的预览与人工确认

Status: implemented

[English](2026-09-08-application-preview-confirmation.md) | 中文

## 问题

共享认证轮次可以读取业务记录，但缺少由应用准备变更的通道，应用只能在另一插件中重复实现会话认证。

## 决策

可选员工传输在已验证登录和不可变会话归属下转发受限的应用请求。能力准入后，模型才获得 `employee_application_preview`。独立同源浏览器确认路由接受已展示的预览编号和摘要，不接受替换的业务值。Harness 之外的应用代码负责业务规则、持久化预览、过期、幂等和审计事务。Cookie 不进入模型消息或持久化会话事件。

## 考虑过的替代方案

**在读取工具中加入写入操作**会错误描述副作用，并使模型能够绕过独立人工确认。

**另建应用专属会话控制器**会重复归属、取消和私有凭据处理。通用传输让现有组件继续承担这些职责。

## 影响

部署必须主动启用并实现身份服务协议；已有只读部署不会获得写入能力。确认时断线不意味着回滚。客户端必须查看权威回执，不能从助手文本重建审批。录制的 Web 场景通过真实 CLI 加载的进程验证预览持久化和独立浏览器确认；单元测试覆盖账号及会话覆盖、跨源调用、未开放配置和资源释放。应用侧业务事务及崩溃恢复仍由应用负责测试。
