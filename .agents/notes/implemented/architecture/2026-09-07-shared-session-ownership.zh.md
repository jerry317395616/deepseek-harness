# Agent Note: 一个 Harness 进程内的账号所属会话

Status: implemented

[English](2026-09-07-shared-session-ownership.md) | 中文

## 问题

用户要求共享一个 Harness，而不是每名员工一个进程。Host 启动 Cookie 不是 Frappe 主体，已有只读代理的 UID 绑定也不能区分共享进程内的调用者。所有员工共用任一种凭据都会消除其授权边界。

## 决策

新增明确限定为会话功能的预览：可信 Unix 套接字身份服务验证签名交接票据与当前启用账号，Session Controller 子路径在模型日志之外分配不可变的 `{site,user}` 归属。创建在成功返回前持久化该会话；列表及分页核验归属，并在返回数据前复查登录。缺少归属、输入错误及身份服务失败均拒绝访问。

员工凭据仅授权此 API。普通 Host API 和全局事件流保留 Host 认证。在排队的 Agent 工作和业务执行能够保留经过验证的调用者之前，不开放员工提示接口。账号启用检查不能代替 Frappe 业务权限。

## 考虑过的替代方案

**共享管理员执行，并在提示中写入角色文字。** 模型指令不能强制执行文档、字段或流程权限。调用身份必须来自认证，并在执行中保持固定。

**一次修改全部远程 API 与界面。** 这会在逐调用身份桥接完成前开放执行。限定接口的预览允许通过双账号测试发现隔离缺陷，无需发布不完整的员工入口。

**为会话归属重命名或新增 Frappe DocType。** 项目禁止结构变更。私有的追加式归属记录无需触碰应用结构或业务记录即可支持重启恢复。

## 影响

针对性 HTTP 与归属测试覆盖双账号、伪造归属、无归属旧会话、不可变文件、响应上限、超时、客户端断开及销毁。Python 测试覆盖重放竞态、复查中退出、账号停用、过期、重启及真实套接字回收。真实进程夹具将两个账号接入同一个 Web 进程；已有会话回放在不改变模型可见契约的情况下验证所属历史。

[指南](../../../../docs/user/guide/employee-shared.zh.md)定义配置和验收边界。共享员工界面、正式单点登录路由、逐轮次调用身份绑定、按权限业务执行及浏览器与负载验收仍待完成。正式路由、服务、Frappe 账号、记录和 DocType 均未改变。
